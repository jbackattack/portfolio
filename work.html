AI test agents, from the Spark prototype to live agents

My team built three live QA agents on the infrastructure team's shared agent framework: a test case analyzer, a test case creator, and a mobile data lookup that queries BigQuery directly instead of waiting on dashboards. The analyzer reviews existing test repos against best practices, and on its first run it found security problems, including passwords stored in insecure places. The creator writes new tests to the same standard.

They followed Spark, a prototype I designed where AI drafts mobile tests and QA acts as the risk assessor and approval gate. Spark included a 13-file agent framework and a Jira epic with eight to nine child stories. It never went to production, because the shared framework made a separate system unnecessary.

Role
Designed Spark; my team built the live agents
Stack
Appium, Java, TestNG, Bitrise, LambdaTest, GitHub Copilot
Status
Three agents built and deployed; Spark was a prototype

One element-ID standard for React Native

Mobile tests break when elements can't be found. I defined one rule for the React Native app: every element gets accessible, a testID, and an accessibility ID, and tests locate elements with Appium's accessibility ID strategy. The same locator then works on iOS and Android.

HuffPost app turnaround

The HuffPost app had limited QA coverage, and releases were often rolled back or paused over critical bugs. I built a QA process that combined manual and automated testing, plus a release process with full testing before every app store submission.

The app's store rating rose from 2.20 to 3.75 in six months, and through 2023 no release had to be rolled back or paused.

Role
Led QA and the release process
Result
Rating 2.20 to 3.75 in six months

A new testing model for the whole tech organization

As the company's needs changed, I designed a different way to test across engineering. I split QA into two teams: a web team for ad revenue and content tools, and a mobile team focused on automation. Product engineers took on their own manual testing, using group testing sessions in place of team demos and the tools QA had used.

The shift was from quality assurance to quality assistance: QA sets up the tools and practices so teams can test well themselves.

Role
Designed the strategy and the team structure

$134,000 saved on outside testing

I reviewed our outside testing contract every year against what it delivered. Usage was low, and what it found was mostly low-priority bugs. I ended the contract, which saved $134,000 with little loss in coverage.

To replace it, my team worked with the infrastructure group to use device and build tools the company already paid for, which made the automation work scale to more devices.

Role
Made the decision and led the transition
Stack
AWS Device Farm, Bitrise

Cutting wasted builds and heading off a vendor price increase

We had a monthly allotment of test builds and runs, and usage kept eating into it. I worked with engineering to trace why, and we found that more builds were being created per test than necessary. That inflated our usage against the budget without testing anything new.

Once the extra builds were removed, we were able to pay for fewer builds each month, and our CI subscription no longer had to grow to cover them. That stopped a potential 20% annual increase.

Role
Found the cause with engineering; kept the subscription from growing

As the apps multiplied, I split the team in two and promoted team leads, which freed me to work on strategy and tooling. I also found team members with coding backgrounds and moved them into automation without letting manual testing coverage slip.

Release checklists, test management, and a third-party integration

Early on I replaced spreadsheets with TestRail for test cases and created release checklists, with product owners and engineering managers, covering the business-critical checks for every release. The checklists became the standard for all of the company's apps.

For a third-party integration in a consumer app, I set up structured joint test sessions with the partner's engineers, who had no test plans of their own. We found more than 50 issues before launch.

Role
Process design and test lead
Stack
TestRail, release checklists

Pack 55 wreath sale app

An ordering and inventory app for a scout pack's wreath fundraiser, including door-to-door sales status. I was the whole team: I decided what it should do, built it with Claude, and tested it, with automatic deploys from GitHub to Vercel.
