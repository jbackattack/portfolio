AI test agents, from the Spark prototype to live agents

My team built three live QA agents on the infrastructure team's shared agent framework (UDF): a test case creator, a test case analyzer, and a mobile data lookup.

They followed Spark, a prototype I designed where AI drafts mobile tests and QA acts as the risk assessor and approval gate. Spark included a 13-file agent framework and a Jira epic with eight to nine child stories. It never went to production, because the shared framework made a separate system unnecessary.

Designed Spark; my team built the live agents

Appium, Java, TestNG, Bitrise, LambdaTest, GitHub Copilot

One element-ID standard for React Native

Mobile tests break when elements can't be found. I defined one rule for the React Native app: every element gets accessible, a testID, and an accessibility ID, and tests locate elements with Appium's accessibility ID strategy. The same locator then works on iOS and Android.

Role
Defined the standard
Stack
React Native, Appium, Java

HuffPost app turnaround

The HuffPost app had gone years without dedicated QA, and releases were often rolled back or paused over critical bugs. I built a QA process that combined manual and automated testing, plus a release process with full testing before every app store submission.

The app's store rating rose from 2.20 to 3.75 in six months, and no release has been rolled back or paused since.

Role
Led QA and the release process
Result
Rating 2.20 to 3.75 in six months

A new testing model for the whole tech organization

When QA staffing shrank sharply, I designed a different way to test across engineering. I split QA into two teams: a web team for ad revenue and content tools, and a mobile team focused on automation. Product engineers took on their own manual testing, using group testing sessions in place of team demos and the tools QA had used.

The shift was from quality assurance to quality assistance: QA sets up the tools and practices so teams can test well themselves.

Role
Designed the strategy and the team structure

$134,000 saved on outside testing

I reviewed our outside testing contract every year against what it delivered. Usage was low, and what it found was mostly low-priority bugs. I ended the contract, which saved $134,000 with little loss in coverage.

To replace it, my team worked with the infrastructure group to use device and build tools the company already paid for, which made the automation work scale to more devices.

Role
Made the decision and led the transition
Stack
AWS Device Farm, Bitrise

Building and leading a distributed QA team

I started with two contract QA engineers and grew the team to as many as seven, working across New York, Ukraine, and Argentina. I led hiring initiatives, including five QA engineers hired through one recruiting partner.

As the apps multiplied, I split the team in two and promoted team leads, which freed me to work on strategy and tooling. I also found team members with coding backgrounds and moved them into automation without letting manual testing coverage slip.

Role
Hiring, structure, and day-to-day leadership

Release checklists, test management, and a partner launch

Early on I replaced spreadsheets with TestRail for test cases and created release checklists, with product owners and engineering managers, covering the business-critical checks for every release. The checklists are still used for all of the company's apps.

For the Tasty app's Walmart Add to Bag launch, I set up structured joint test sessions with Walmart's engineers, who had no test plans of their own. We found more than 50 issues before launch.

Role
Process design and test lead
Stack
TestRail, release checklists
